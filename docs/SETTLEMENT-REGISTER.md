# Settlement register

Everything outstanding, in one place, with a category and — where something is blocked — the
exact thing that unblocks it.

The point of this document is that **no outstanding item lives only in a conversation.** A gap
that was discussed once and never written down is indistinguishable, six months later, from a
gap nobody noticed. Each entry below is one of four things:

| Category | Meaning |
| --- | --- |
| **BUILT** | Implemented, tested, reachable over HTTP. |
| **DEFERRED — BY DECISION** | Could be built today. Deliberately is not. The reason is stated and is a reason, not a shrug. |
| **BLOCKED — ON EXTERNAL** | Cannot be built correctly without something from outside this repository. The unblocker is named. |
| **NOT STARTED** | No decision, no blocker. Just not done yet. |

Last reconciled against the tree: migration `0025`, 106 HTTP routes, 1,174 tests
(574 domain · 443 db · 119 api · 21 worker · 17 contracts).

## 2. DEFERRED — BY DECISION

Buildable now. Deliberately not built.

### 2.1 BullMQ and Redis

`docs/architecture/03-tech-stack.md` names BullMQ. The worker uses PostgreSQL
`SELECT … FOR UPDATE SKIP LOCKED` instead.

The outbox exists to eliminate a dual write: the job and the ledger effect commit together
only while the job lives in the same database as the effect. Pushing to Redis from the writing
transaction reintroduces exactly the inconsistency the pattern prevents. A second datastore
for one nightly job is operational burden with no offsetting gain.

**Revisit when** something needs cross-process rate limiting or fan-out beyond a single poller
— a real MyInvois submission rate limit would be the trigger.

### 2.2 A concrete payment gateway client

`PaymentGateway` is a port with a `FakeGateway` behind it, so the whole collection flow is
exercisable end to end. The Billplz / iPay88 HTTP client is not written.

Distinct from §3.3: writing the *client* is blocked on credentials, but the *decision* not to
pick a vendor yet is ours. A client written against endpoints nobody can exercise looks
finished and probably is not.

### 2.3 `status = 'REVERSED'` on documents other than journal entries

`reversePostedEntry()` marks the reversed journal entry. Invoices and bills keep their own
lifecycle status and are not touched, because a credit note does not "reverse" an invoice in
the ledger sense — it is a document in its own right with its own number and its own tax
point.

## 3. BLOCKED — ON EXTERNAL

Migration `0018` made this class of item enforce its own provenance: a value that arrives
later cannot be stored without citing where it came from. What follows is what is still
waiting, and for what.

### 3.1 Withholding tax rates

`wht_rate` ships **empty**, `legislation_ref` is `NOT NULL`, and `paySupplier` fails loudly
rather than defaulting.

**Unblocked by:** the applicable LHDN Public Ruling per payment type, plus the relevant
Double Taxation Agreement article where a non-resident payee's country changes the rate.
A rate without both is not a rate.

### 3.2 MyInvois wire format

`einvoice.ts` models submission state, validation and retry. What crosses the wire to LHDN is
not written. `apps/worker/src/handlers/einvoice.ts` queues `invoice.issued` and
`creditnote.issued` and stops there.

**Unblocked by:** LHDN's MyInvois SDK documentation and a sandbox client id/secret. Field
names, the UBL profile in use, and the signature requirements cannot be guessed — a document
rejected at submission is recoverable, a document *accepted* with a wrong field is not.

### 3.3 Payment gateway credentials

**Unblocked by:** Billplz or iPay88 sandbox credentials, and their signature scheme
documentation.

### 3.4 The DuitNow merchant template

The EMVCo TLV encoder and CRC-16/CCITT-FALSE are implemented and tested against published
vectors — that part is a public standard. The PayNet-specific pieces are not: which of tags
26–51 carries DuitNow, the AID/GUID, and the merchant id format.

**Unblocked by:** PayNet's DuitNow QR merchant specification. A guessed template produces a QR
that scans cleanly and pays the wrong party.

### 3.5 e-Invoice unit-of-measure codes

`einvoice_uom_code` is seeded empty and every code is refused, with a message that says why.

**Unblocked by:** LHDN's published UOM code list.

### 3.6 SST-02 box mapping

Which ledger figure lands in which box of the return.

**Unblocked by:** RMCD's SST-02 form and its completion guide.

### 3.7 Per-bank statement import profiles

Maybank, CIMB, Public Bank and the rest each export a different CSV. `0018` requires a saved
profile to record which real statement it was derived from.

**Unblocked by:** sample statement exports — the header row is enough. A guessed column map is
precisely the plausible-but-wrong failure that explicit profiles exist to prevent.

## 4. NOT STARTED

No blocker. Not done.

### 4.1 `apps/web` — the Next.js application

There is no user interface. Everything in this repository is reachable only over HTTP with a
bearer token. This is the largest single outstanding item by effort, and the one a customer
would notice first.

### 4.2 Onboarding

**There is no way to create an organisation or a fiscal year through the API.** Both are
seeded directly in every test, including the year-end e2e, which has to insert `fiscal_year`
and `fiscal_period` rows on the admin connection before it can close anything.

So a real first-time user cannot get to a state where any of the 106 routes is useful. Small
in code, load-bearing in practice: an organisation, its chart of accounts, its fiscal calendar
and its posting account map, created together in one transaction.

### 4.3 Attachments

No table, no object storage, no route. A bill without its scanned invoice is half a record.
Needs an object store decision (S3-compatible) before the schema is worth writing.

### 4.4 Outbound notification

`financial_event_log` records what happened; nothing tells anybody. No email transport is
configured. Invoice delivery, payment receipts and approval requests all want it.

### 4.5 Document rendering — PDF and XLSX

An invoice a customer can be sent, and a report an accountant can open in Excel. CSV export
exists (`packages/domain/src/csv.ts`, with the formula-injection guard); PDF and XLSX do not.

### 4.6 Per-currency price lists

`item` carries one price in one currency. `issueInvoice` refuses a base-currency item price on
a foreign-currency invoice rather than converting silently — correct, and it means selling in
two currencies needs a price list per currency.

### 4.7 OpenAPI response schemas

The generated document carries request schemas, permissions and error responses. Success
response bodies are not modelled, so a generated client knows what to send and not what it
gets back.

### 4.8 `packages/ui` and `infra`

Named in `CLAUDE.md` as planned. Neither exists. `infra` (Terraform) is not worth writing
before there is something to deploy beyond the API.

## 5. Defects found and fixed while compiling this register

Recorded because a register that only lists future work implies the past work was clean.

| Defect | Consequence had it shipped |
| --- | --- |
| `fiscal_year.status` was never checked by `assert_period_open()` | A year marked CLOSED accepted postings for as long as any of its periods was open — which was always, since nothing closes periods automatically. Filed figures could move underneath the filing. |
| `journal_entry.reversal_of_id` was declared in `0001` and written by nothing | Every reversal in the system, including FX revaluation reversals, reported `reversalOfId: null` in the general ledger. Rule 1 requires corrections to *reference* the original; nothing referenced anything. |
| The income statement counted the closing entry | A closed year reported zero trading. The entry is dated inside the year on purpose — it has to be — so the P&L now subtracts it explicitly (`yearEndCloseMovement`). |
| A bodyless `POST` with `Content-Type: application/json` answered 400 | `POST /v1/fiscal-years/:id/close` and `POST /v1/tax-returns/:id/submit` were unreachable from any HTTP client that sets the header by default, which is all of them. |
| `@Doc({ request: … })` named the wrong schema on two routes | `POST /v1/periods/:id/status` advertised the journal-entry schema; `POST /v1/tax-returns/:id/submit` advertised the amendment schema and takes no body. The conformance test checks that a schema *exists*, not that it is the right one. |
